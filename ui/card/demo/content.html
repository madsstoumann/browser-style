UI: Card — <ui-content>

Everything that controls the content column: the scl() scale (decoupled body + headline ramp), hl() headline sizes (incl. 3xl), the four group families — eb() / hl() / tx() / mt() — for tone, weight and text-shadow, the theme= themes, every data-part, pad()/gap() spacing, responsive size, scrollable content, and the core surface tokens. All driven by variant / content tokens — no JavaScript. Media-backed treatments live in media.html.

See also: cards.html (the card gallery) · media.html (the <ui-media> side) · ui-card-tokens.md (token reference).

  • typography — the type ramps (headline / body) and the per-part proportional scale

Typographic scale — scl()

content="scl(sm | md | lg | xl)" (default md) sets two container-driven clamp() ramps at once — a gentle body scale (eyebrow / summary / meta / tags) and a more aggressive headline scale. Decoupling them means a big card gets a display-size title while the body copy stays readable. Both also grow/shrink with the card's own width (cqi).

Content parts — the full anatomy

Parts are styled by the data-part attribute, not the tag name, so you pick the semantically correct element. Each part has its own font-size / colour / weight / gap tokens (all relative to --ui-content-fs by default). The caption over the image is a <ui-chip> positioned with chip(bs) on the card's media= (see media.furniture.html). The second example is a bare <ui-content> — no <ui-card>, no <cq-box> — showing the primitive works standalone with its own content= attribute.

Tags (data-part="tags") are a <ul>/<li> list whose items are either plain links — <li><a>, rendered as the default pill (this is what render.js emits; see the horizontal strip below) — or <ui-chip> children. A default <ui-chip> (no attributes) is the same grey pill (grey on light, darker grey on dark — see the three theme cards below); add theme= (red/orange/green/blue/accent/dark/light/subtle) or variant= (light/outline) for the full palette (see ui/chip), as on the two anatomy cards above.

Placement — plc(<cell>)

The same nine logical cells as the media furniture grid (ts tc te · cs cc ce · bs bc be), but via align/justify, not absolute positioning: the block letter drives justify-content, the inline letter align-items. The full-width row cards below (media asr(1/1), content beside it — alternating row-r/row) give the column room on both axes so every cell is visible; each also sets rds(non) (square card) and wid(sm), whose 35ch measure lands at roughly half to two-thirds of the column — narrow enough that the inline letter has somewhere to move the text. The text alignment follows the column: centered cells add tal(ctr), end cells tal(end), start cells keep the default. lg:pad(lg) opens the inner padding up once the card crosses the lg: container tier. All system tokens, no inline styles.

plc(ts)

Top start

Rows gather at the block start, each aligned to the inline start. This is closest to the no-token default.

 plc(tc)

Top center

Rows gather at the block start, each centred on the inline axis. Note the text itself still reads start-aligned.

 plc(te)

Top end

Rows gather at the block start, pushed to the inline end. In RTL every cell mirrors automatically.

 plc(cs)

Center start

The column centres vertically beside the square media. A common editorial look for side-by-side cards.

Centred on both axes. Combine with tal(ctr) below when the text should centre too.

 plc(ce)

Vertically centred, hugging the inline end. Pairs naturally with a row card whose media sits at the start.

Rows sink to the block end, aligned to the inline start. The classic caption position.

Width — wid(<size>)

Caps the text measure — each content row's max-inline-size. The no-token default is the prose measure --width-prose (65ch); the ladder is sm 35ch · md 50ch · lg 65ch · xl 80ch · 2xl 100% (no cap). No xs step — the type ladders start at sm; only the spacing scale has an xs. The cap rides the rows, not the column, so plc()'s inline letter still places a narrow measure within a wide column.

wid(sm)

35ch measure

The tightest step — sidebar notes and captions, where a long line would dwarf the type.

 wid(md)

50ch measure

A compact reading column — short summaries stay comfortable without spanning the card.

 default · wid(lg)

65ch prose

The no-token default — the classic prose measure from --width-prose, also reachable explicitly as wid(lg).

 wid(xl)

80ch measure

A wide editorial column — leadier text for hero rows where the default would feel narrow.

 wid(2xl)

Full width

No cap at all — every row spans the column. Use sparingly; long lines cost readability.

Text alignment — tal()

tal(start) (the no-token default) · tal(ctr) · tal(end). Pure text-align — combine with plc() to move the block and align the text independently. (The old combined ctr/end bare flags are removed: ctr ≈ plc(tc) tal(ctr), end ≈ plc(te) tal(end).) Like plc(), tal() sits under the ovr() slot, so an inherited group-level alignment never overrides an overlay card's cell-derived one.

tal(start) · plc(cs)

Start aligned

The reading default — ragged-right in LTR, ragged-left in RTL. Explicit tal(start) also resets an inherited centre.

 tal(ctr) · plc(cc)

Centered text

Centred type over a centred block — the symmetric hero treatment, without touching the overlay system.

 tal(end) · plc(ce)

End aligned

Type ragged toward the media — a mirrored look for alternating rows like these.

Headline sizes — hl(<size>)

hl(sm | md | lg | xl | 2xl | 3xl) swaps the headline stop only — the body copy stays put. Unlike scl() (which moves both ramps together), hl() decouples a display-size title from readable body. 3xl is the display step (formerly poster).

Text-shadow — shd (overlay legibility)

The shd flag adds a legibility text-shadow to a group. Its main job is overlaid text over a scrim: a host ovr() automatically shadows the headline + eyebrow, and hl(shd)/eb(shd) opt any group in explicitly. (This is the only media-backed example on this page — for the rest of the overlay/scrim system see media.html.) Retune with --ui-content-text-shadow or disable via style="--ui-content-heading-text-shadow: none".

Responsive size — lg:scl() / lg:hl()

Resize the window (or the card's container) across the lg breakpoint (44rem / 704px): below it the base size applies, at/above it the lg:-prefixed size takes over. Only size tokens are prefixable — tone and weight stay static.

scl(sm) lg:scl(lg)

Body + headline both jump at lg

scl() moves both ramps together — this whole block steps up once the card is at least 44rem wide.

 hl(md) lg:hl(3xl)Headline alone jumps to 3xl at lg

hl() decouples the title: the summary size is unchanged, only the headline leaps to the 3xl display clamp when wide.

Scrollable content — content="scr"

Add content="scr" to cap the content height and make it scroll, with a CSS-only fade-shadow on the masked edges (a scroll-driven animation). Cap the height with --ui-content-scroll-bs.

scr

A long read

Scientists have made a breakthrough in quantum computing that could change everything we know about processing power.

The implications stretch across cryptography, materials science and drug discovery — fields long bottlenecked by classical compute.

As you scroll, the top and bottom edges fade via a mask animated on a scroll-timeline — no JavaScript.

When you reach the bottom, the trailing fade lifts so the final line is fully visible.

Resize the card and the cap still holds at --ui-content-scroll-bs.

3. Long policy text, changelogs and FAQs fit this pattern well.

4. Everything stays within the card's rounded clip.

5. Scroll on to confirm the bottom fade releases at the end.

6. The end.

content="scr(x)" flips the axis: a horizontal scrolling row with a left/right fade — for a strip of chips, tags or thumbnails that overflows the card. Bare scr (= scr(y)) stays vertical. This strip is deliberately made of plain-link tags (<li><a>) — the default-pill fallback (exactly what render.js outputs today) — to prove it still renders and scrolls without <ui-chip>.
