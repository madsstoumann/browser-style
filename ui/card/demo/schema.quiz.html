UI: Card — Schema.org Quiz Carousel

Three takes on the schema.org Quiz card: first the gated carousel, then the same carousel with free navigation (all three dots and both arrows live from the start — no required, no gate rule), then the original three-fieldset card, unchanged, for comparison. The carousel: one <ui-card> per Question — a <ui-media> plus a <ui-content> holding that question's <fieldset> — inside a <lay-out overflow media="nav(end) arw(drk)"> scroller — nav(end) puts the dots + arrows inside the content column after the fieldset, repeating the column's padding-block-end above and below the row, and arw(drk) fills the arrow discs; content="wid(2xl)" lifts the prose measure so each fieldset spans the card.

The next arrow stays disabled until the current question is answered, with no JavaScript: one radio per group is required, and the scroller's gate token hides every card following an unanswered one (:has(:invalid) ~ *, carousel.css). The scroller then ends at the current question, so the native ::scroll-button() is :disabled (dimmed by carousel.css), swiping cannot overshoot, and the marker dots appear one by one as questions unlock. The gate is answered-based, not correctness-based — a wrong pick still advances (its verdict chip tells you so); after the last question the arrow simply stays dimmed. In browsers on the carousel polyfill (no native ::scroll-marker), all three dots render from load and the next button re-checks its disabled state on scroll/resize.
