Native video

Four native-video setups. native video: the browser's own <video controls> — no <ui-play>, no JS. The rest put a <ui-play> over a chrome-less <video> — a custom control, an autoplay loop, and a custom poster that shows until play. All keep a stable frame via asr().

YouTube — provider="youtube"

Same facade as the Vimeo embeds — data-preview is provider-agnostic: here a static <img data-preview> poster (Vimeo uses an animated <video data-preview> loop) sits over a lazy <iframe>, lifted by z-index so source order doesn't matter. The <ui-play> click drops the poster, appends autoplay=1 and hands off to the YouTube player. (An iframe isn't an HTMLMediaElement, so it uses the click facade, not command="--play-pause" — that's native <video> only.)

YouTube — no-JS facade via srcdoc

No JavaScript at all. The <iframe srcdoc> renders a poster + a real <a> link; clicking it navigates the iframe itself to the ?autoplay=1 embed — the click is the user gesture autoplay needs. src is the fallback for browsers without srcdoc support. No provider, so video.js never touches it.

youtube

Vimeo — no-JS facade via srcdoc

The same srcdoc trick works for Vimeo: poster + <a> → clicking navigates the iframe to ?autoplay=1&muted=1. Cyan circle badge to match <ui-play>'s Vimeo brand. Public/embeddable video only (a domain-locked one would 401).

YouTube — looping preview in front

YouTube exposes no preview clip (no MP4 API, and the animated-thumbnail WebP is session-gated), so the 2-second loop is a clip we host ourselves — cut from the source with yt-dlp + ffmpeg (see video.md). Same <video data-preview> facade as the Vimeo cards, now over a YouTube <iframe>.

Native video + <ui-media> effects

The frame treatments apply to a native <video> just like an image — tnt() tint, shp() shape/morph, hov() effects and furniture all clip/blend/overlay the video. Videos autoplay muted; hover the shape/blur/tint tiles.
