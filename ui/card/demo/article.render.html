UI: Card — Article View Transition

Each teaser card links to its own page: articles/article.html, articles/news.html and articles/news-paywall.html — the third is the paywalled article: same engine, the prose-article-gate preset fades the body's tail and a subscribe wall (an Offer card) follows the article; its structured data is isAccessibleForFree: False plus hasPart → WebPageElement naming the gated part. All three documents opt in with @view-transition { navigation: auto } and carry the same per-article view-transition-names — set via data-view attributes and the CSS attr() rule, no inline styles — so the whole card morphs into the full article across the navigation, and morphs back via the browser Back button. Every page here is pre-rendered by articles/build.js (the SSR engine): static markup on both sides is what makes the capture reliable in both directions. The full view renders the body as itemprop="articleBody" instead of the teaser summary, from the same UCF instance. The full view uses the prose-article preset: the summary stays visible as the standfirst and the byline moves up under it (byline: lede), at reading scale.

Browser support. Chromium 133+ morphs natively. Safari 18.2+ supports cross-document transitions but not typed attr(), so the names come from ui/base/polyfills/attr-fallback.js (loaded at the end of this page) — without it the navigation still transitions, just as a plain cross-fade. Firefox has no cross-document transitions and navigates instantly. prefers-reduced-motion: reduce disables navigation transitions by design, and the pages must be served over http — opened from file:// there is no transition (and the root-absolute base CSS 404s).
