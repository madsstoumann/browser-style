UI: Media — Lightbox

A <ui-lightbox> furniture button (default area bottom-start) lifts the existing <ui-media> into the top layer as a fullscreen gallery. The frame carries a static popover attribute + an id; the button is a plain invoker — command="toggle-popover" commandfor="<id>" — so opening and closing needs zero JavaScript: the platform handles Esc, light-dismiss, focus and ::backdrop. Same DOM in both states — no re-render, no attribute churn. While open the button doubles as the close affordance (the glyph morphs to an ×). Open/close is animated: a clip-reveal + backdrop fade in pure CSS (@starting-style can only drive the ::backdrop — the frame itself is always rendered, so its entry is a keyframe and the overlay transition carries the fade-out), upgraded to a full card ↔ fullscreen View Transition morph when lightbox.js is loaded.

Open-state presentation is the open: token family: a nav frame opens as a fullscreen carousel by default; open:grid(2c|3c|4c) presents the same children as a scrollable grid. Marker furniture (chips, stickers, beacons, marquees, save) hides while open — opt out with the bare open:furniture flag; ui-play always stays. See also carousel and collage. One authoring note: give gallery images srcset + sizes="auto" + loading="lazy" and the browser re-selects a higher-resolution candidate automatically when the frame goes fullscreen (a static sizes tuned to the card never upgrades) — the ui-media-srcset.js Cloudflare path emits exactly this by default.

Carousel → fullscreen carousel

The carousel-page card plus three things: popover + id on the frame, lightbox(bs) in the tokens, and the invoker button. While closed the button is position: sticky-pinned to the scrollport (plain furniture scrolls away with the slides); while open the same carousel keeps snapping, swipe and keyboard — simply viewport-sized. Dots and arrows are real elements here: the native ::scroll-marker/::scroll-button pseudos don't follow a popover into the top layer (they'd paint behind the ::backdrop — a current-Chromium limitation), so lightbox.js injects the /ui/carousel/polyfill/carousel-controls.js DOM controls on popover frames — in both states, so closed and open stay continuous. Opening and closing itself still needs no JS; without lightbox.js the open carousel falls back to swipe, keyboard and a thin scrollbar.

Change the nav style while open — media-open=

The open state can switch into any existing nav style. The control stems (nav/mrk()/arw()/tmb()/axis()) are substring-matched, so their spellings can't ride inside media= behind an open: prefix — instead they live in the companion media-open= attribute (same element as media=), and lightbox.js swaps just the control words of the media string on open, restoring them on close — with slide continuity across the swap. Left: dots while closed → the carousel-page rail (axis(y) nav(mrk) mrk(tmb) mrk(rail)) fullscreen, thumbnails auto-derived from the slides. Right: arrows-only while closed → dots + arrows while open (the controls are built as the union of both states). Without JS the lightbox simply keeps the closed nav style.

The invoker follows the carousel's ink

The button is furniture pinned on the media, so it takes its disc and glyph from the same bundle the arrows use — --ui-carousel-arrow-plate and --ui-carousel-arrow-ink — instead of the page surface. In a band (nav(blw)) the arrows are a bare masked glyph with no circle, so the invoker drops its disc too and inks itself from the card; with arw(drk) it takes the dark circle and light glyph. Nothing here tracks color-scheme on its own, which is what used to make a dark disc appear next to white arrows. Override per element with lightbox(<hue>), ink=/fill= or lightbox(non).

Collage → fullscreen collage

The collage is a <lay-out> inside the frame — and its breakpoints are viewport-keyed, so in the fullscreen lightbox (where the frame IS the viewport) the same grid simply re-tiers to its largest pattern. The chip and sticker hide while open (default); the per-tile hov(zoom) keeps working.

Carousel ↔ grid, at runtime

A second invoker inside <ui-lightbox> carries the custom command="--lightbox-layout" (handled by ui/card/lightbox.js — the one JS-enhanced section on this page). It only shows while the lightbox is open, and flips the frame between fullscreen carousel and grid via data-lightbox; closing resets to the tokens.

Video in the lightbox

Play buttons are the exception to the furniture hiding: a video gallery keeps its <ui-play> control while open (video.js supplies the play-pause media-command polyfill, as on the other media pages).
