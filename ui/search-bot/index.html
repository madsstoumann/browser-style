UI: Search Bot

<ui-search-bot> puts a conversation on top of a search box. It wraps a <ui-search> — the form that works without script, is the ?q= link, the SearchAction target and the WebMCP tool — and, with script and an api=, streams an answer to the same question: a summary in words, the pages it came from, follow-ups. Four modes: inline under the box, overlay (a window), search (full screen), chatbot (docked by a floating button). Without a box to wrap it brings its own form. This page has no backend: a mock stream reads /ui/search/data/demo.json.

Header: Ask beside the box

The header above wraps today's search box. Typing shows quick results (that is <ui-search>); the Ask button, or Enter with trigger="submit", opens the answer in an overlay with its own field for follow-ups. context="site" is sent along, so the endpoint knows what to answer from. An agent's submit (WebMCP) is left to the form, which answers with the search response.

Inline, on a results page

mode="inline": the wrapped form is the input, and the answer streams in under it, in the page. Enter asks (the bot takes the submit before <ui-search> runs its search), the box is cleared, and with sync-url on the box the address still becomes ?q=…, so the link opens the plain results without script.

Standalone, in Danish

No box to wrap: the bot draws its own form. Every word comes from a label-* attribute; multiline swaps the field for a textarea where Enter sends and Shift+Enter breaks the line.

Floating: chatbot and full screen

Bottom right, mode="chatbot" docks a panel by its trigger (position="be", the nine-cell grid ts tc te / cs cc ce / bs bc be). Bottom left, mode="search" grows to the full screen — that one streams from a live NLWeb worker, so it needs the network. Both remember the thread (preserve-history) and reopen where they were (preserve-state).

The stream

api= is the endpoint; the adapter named by provider= (nlweb, the default, or aisearch) builds the query string and reads each message. The endpoint answers text/event-stream: hits first (result_batch), then the summary in pieces (summary), then complete. A trailing References block of [n] url lines turns every [n] in the text into a link. See readme.md § The stream.
